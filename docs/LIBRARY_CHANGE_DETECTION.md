# 曲库变化检测策略

## 目标

大曲库空闲时不再每 180 秒遍历全部音频文件，同时保留重启、事件丢失和不支持文件通知时的正确性。

## 当前实现

- Linux 优先使用 `inotify`，递归监听已配置曲库目录。
- 只把受支持音频/CUE 文件变化和目录创建、删除、移动标记为 dirty。
- 每次事件增加 generation；扫描完成时只有 generation 未变化才清除 dirty，避免扫描期间到达的新事件丢失。
- `IN_Q_OVERFLOW`、监听创建失败或读取错误会标记 overflow，并回退完整签名扫描。
- Windows 和不提供 inotify 的系统保持轮询回退，仅用于开发和兼容。
- 符号链接目录不加入监听树；扫描、签名和 CUE 引用均使用真实路径边界，指向曲库外的文件不会进入索引。

## 正确性边界

inotify 是“需要重新核验”的提示，不是曲库数据库本身。检测到变化后仍计算文件签名，再决定是否解析 Tag 和替换索引。取消、超时或扫描异常保留上一个有效索引。

## 验证

`src/tests/test_library_cache.py` 覆盖空闲跳过 O(n)、dirty/clean generation、事件解析、溢出回退、CUE 越界和符号链接逃逸。
