# 逐轮审查与修复的记账口径

本文件把负责人已经裁定、此前只存在于会话里的口径落到磁盘，供任何一次接管复算。
它不新增待办、不改动任何条目的判据、不记录任何凭据。
`src/tests/test_device_todos_migrated.py` 把本文件与 `TODO.md` 双向核对：
两侧单独改动即判红，因此本文件的数字不是注释而是被约束的数据。

## 一、桶口径（裁定来源：X2=B，新一代 C3 复核）

`TODO.md` 在长期观察段段首留有一行桶归属声明，内容锚点为 `R138 X2=B 桶归属`。
自该行之后直到文件末尾的未勾条目属于第五桶「长期观察」：它们只登记观察口径，
没有当轮可执行的关闭动作，**不计入终止分母**。四桶自此固定为：

| 桶 | 判据 | 计入哪条终止条件 |
| --- | --- | --- |
| 代码 | 段外可离线验证的未勾条目 | (1) 可离线验证的代码侧待办清零 |
| 设备／外部 | 设备段条目，原文冻结并迁册 `external-acceptance.md` | (2) 逐条裁定后移出逐轮任务 |
| 需决策 | 负责人尚未裁定的条目 | (3) 需决策桶为 0 |
| 长期观察 | 段首声明之后的登记条目 | 不计入任何一条 |

重算规则沿用写在纸面上的那一条：设备段与决策段按节标题取，段外只登记项归第五桶，
其余归代码桶。行号一律以磁盘实测为准，本文件不写行号——每记一轮就有一批条目被 prepend
到 `TODO.md` 顶部，任何写死的行号在第一次被使用时就已失效。

- 实测口径锚点：`observation-open-count = 2`

守卫读的是上面这个数，并与 `TODO.md` 声明行之后的未勾条目实测值比对。

## 二、0-close 记账口径（裁定来源：Q2=A、X3=A+C，新一代 C8 正式化）

设备段处置轮与文档段轮如实登记「**净关闭 0 条**既有代码待办」，同时写明本轮收益记在哪：
设备段收益记在终止条件 (2)，口径与文档收益记在本文件的落点上。既不为凑关闭数新立代码
待办，也不把非代码收益谎报成代码关闭。反增长约束里「本轮新立的可离线代码项不得超过关闭数」
对这类轮次的读法是 0 ≤ 0。深读登记轮另按 X3=A+C 以「欠读行数下降」计进展。

## 三、真机取证分档白名单（裁定来源：D5/D8，新一代 C5）

第一档＝只读取证＋放置无标签样本曲＋播放＋抓服务端日志。禁止：重启设备上的服务、
改动服务端配置、部署新构建、停止正在运行的服务。任何涉及停止服务的动作都要
**先向负责人请示**再执行。取证结束必须复验：设备 `/tmp` 无本轮残留、`/etc/resolv.conf`
哈希探测前后一致。第二档（安装第三方控制点等改变设备软件栈的动作）不属于白名单，
需另行逐条批准。设备登录凭据由负责人持有，**一律不写入仓库任何文件**。

## 四、终局收口形式（裁定来源：D1，新一代 C7）

本仓库无 remote、开源但暂不托管。终局轮只跑一次完整 `tools/test_offline.ps1`、
做逐文件哈希抽查、出结题报告；**不 push、不打 tag、不改 `.gitignore` 与 `.gitattributes`**。
若需要留一个可回溯点，由负责人另行明示授权。

## 五、深读轮前置取证（新一代 C4）

代码桶现存的两条深读债（欠读清单条、`app.js` 浅读面符号计数条）在动手前一律先读现状：
现状已落实的按**证伪关闭**处理，并把结论转成回归守卫；未落实才按既有裁定实作。
符号计数轮必须能复算出历史登记值，复算不出即停下如实报告，**禁止改写历史数字**。

## 七、真机观察项迁出为「以后的目标」（常设指令 2026-09-22，落地轮 R157）

负责人给出两条常设指令，效力高于此前「逐条回头征询」的做法：

1. 此后所有需要裁定的事项，一律按执行体自己给出的建议执行，不再逐轮回头确认；
2. 凡需要真机验证的事项全部单独列出，**移出当前逐轮执行的目标**，作为「以后的目标」另册推进。

第二条在本轮落到磁盘：长期观察桶原有 13 条，其中 11 条只能靠真机或外部材料推进（WebView、
真实设备、真实网络、设备侧、外部验收、fnOS 宿主桥接），已逐字迁入 `docs/REAL_DEVICE_GOALS.md`
并给固定编号 G01～G11，每条配一行「真机口径」与开工前置；`TODO.md` 原位各留一行非 checklist
的迁出指针。余下 2 条（首屏离线性能回归、服务端资源上限与模块边界拆分）不含任何真机依赖，
留在桶内，因此第一节的实测锚点数字由 13 改为 2——两侧必须同轮同改，只改一侧守卫即判红。

口径边界：**迁出不等于结案**。这 11 条与设备台账里的 45 条一样，仍要在真机上有读数、或有一份
记录的「不可取证」裁定才算结案；在此之前，任何一轮既不得把它们当代码待办推进，也不得拿离线
结果去勾选。终止条件 (2) 的满足形式随之改变：由「逐轮把设备项清出任务列表」变成「结构性成立＋
逐条待真机裁定」——逐轮任务里已不含需要真机的条目，逐条结案归入以后的目标。

- 新增桶、新增记账口径或放宽白名单，都属于需要负责人裁定的变更，不得由执行体自行改判。
