# fnAudio 阶段一、阶段二待完成与优化清单

本文档整理 0.1.5 阶段一「MPD 本机播放」与 0.1.6 阶段二「SQLite 音乐库数据库化」中尚未完全完成、仍需继续优化或需要真机验证的项目。后续开发按本文档逐项推进。

## 阶段一：MPD 本机播放

### 1. MPD 进程监督（已完成）

- [x] 避免重复启动多个 MPD 私有实例。
- [x] 应用停止时彻底清理 fnAudio 自己启动的 MPD 进程。
- [x] MPD 崩溃后自动重启。
- [x] MPD 启动失败时记录日志并给出明确错误原因。
- [x] 检查并清理历史残留 MPD 进程。

完成说明：

- `MpdService.start()` / `restart()` 在当前 supervisor 未持有运行中 MPD 时，会清理旧的 app-private MPD 实例。
- `MpdService.stop()` / `shutdown()` 会停止 MPD idle 监听线程，再停止 MPD 进程。
- 残留进程识别限定在当前 fnAudio MPD 配置路径或数据目录，避免误杀系统其他 MPD。
- `0.1.22` 的应用停止脚本增加私有 `mpd.conf` 进程扫描，PID 文件缺失或失效时仍会清理残留 MPD。
- 已在 `198.51.100.24` 执行停止/启动回归：停止后服务与 MPD 均退出，启动后仅保留一个 fnAudio 私有 MPD 实例。
- `0.1.22` 经应用中心正式停止验证后发现监督器与停止脚本存在竞态；`0.1.23` 已调整为先停止服务、再清理私有 MPD，已通过应用中心正式停止/启用回归。
- 崩溃自动重启继续由 `ProcessSupervisor` 负责。

### 2. MPD 状态监听（已完成）

- [x] 使用 MPD `idle` 机制替代或减少 1 秒轮询。
- [x] 播放、暂停、停止、上一曲、下一曲、seek 后状态及时同步到状态缓存。
- [x] 播放结束后自动进入下一首时，状态同步要稳定。
- [x] 确认 MPD 状态与 Playback Core 状态一致。

完成说明：

- `MpdService` 增加 MPD 状态缓存，`idle` 监听到 player / mixer / playlist 等变化后会立即刷新缓存。
- 播放、暂停、停止、seek 等控制命令执行后会主动刷新 MPD 状态缓存。
- 状态接口返回缓存状态，并在播放中根据缓存时间推算当前进度，减少重复 probe。
- 已在 `198.51.100.24` 触发 MPD playlist 变化验证：`idle.changed` 返回 `changed: playlist`，`cached_at` 与 `last_event` 同步刷新。
- 已在真实 TEAC UD-301 上验证 MPD 队列下一曲：核心状态、MPD 当前曲目和 DAC 输出同步切换；随后停止后 MPD 正确恢复为 `STOPPED`。
- 已在真实 TEAC UD-301 上验证 seek、暂停、继续和上一曲：seek 至 15 秒后 MPD 实际位置为约 16 秒，`PAUSE` / `PLAY` 状态和曲目切换均正确同步。

### 3. USB DAC 能力探测（已完成，已在真实 USB DAC 验证）

- [x] 准确识别 USB DAC 名称，例如 TEAC UD-301。
- [x] 探测最大 PCM 采样率。
- [x] 探测最大 PCM 位深。
- [x] 探测是否支持 Native DSD。
- [x] 探测是否支持 DoP。
- [x] 探测是否支持硬件音量。
- [x] 探测 ALSA Mixer 名称。
- [x] 将探测结果提供给前端用于显示和播放策略判断。

完成说明：

- `/proc/asound/cards` 解析修复为按“空格-空格”分隔，避免 `USB-Audio - TEAC UD-301` 被误拆成 `Audio - TEAC UD-301`。
- USB 判断增加 sysfs 路径辅助，不只依赖设备名称里是否包含 `usb`。
- TEAC UD-301 预设能力保留：PCM 最高 192kHz，最高 32bit，DSD 2.8MHz / 5.6MHz。
- 已用模拟 ALSA 数据验证：ALC897 Analog 和 HDMI 被过滤，只保留 `TEAC UD-301`。
- 已在真实飞牛实体机验证 `TEAC UD-301`：识别为 `hw:0,0`，最高报告 PCM 为 352.8kHz / 32-bit，支持 DSD 2.8MHz / 5.6MHz。
- 真机环境未安装 `amixer`，因此硬件 Mixer 控制仍显示为不可用；不影响 MPD 音频播放。

### 5. MPD 播放兼容性验证（已完成首轮真实 USB DAC 验证）

- [x] 测试 MP3：实际输出 `44.1kHz / 24-bit / 2ch`。
- [x] 测试 FLAC：实际输出 `96kHz / 24-bit / 2ch`。
- [ ] WAV：真机当前音乐库没有可用测试样本。
- [x] 测试 M4A：实际输出 `44.1kHz / float / 2ch`。

- [ ] DFF：真机当前音乐库没有可用测试样本。

- [x] 测试 TEAC UD-301 真机输出。
- [x] 明确 DSD 为 MPD Native DSD 输出，不经过 PCM 转码，也未使用 DoP。

说明：

- 真实验证日期：2026-08-02。每次测试后均已调用停止，MPD 状态恢复为 `STOPPED`。
- 后续仅需在用户补充 WAV、DFF 或更高规格 PCM 样本时扩充格式覆盖，不阻塞当前 MPD 本机播放能力。

### 6. 浏览器输出与 MPD 输出边界（已完成）

- [x] 远端浏览器播放继续走浏览器输出。
- [x] NAS USB DAC 播放才走 MPD。
- [x] 前端选择播放设备时，让用户明确知道声音输出在哪里。
- [x] 切换播放目标时停止当前目标播放，避免关闭应用后远端继续播放。

完成说明：

- 浏览器播放目标是 `local`，由前端 `<audio>` 负责播放和停止。
- USB DAC 播放目标是 `mpd:<alsa_id>`，由 MPD 插件负责播放、暂停、停止、seek 和状态同步。
- DLNA/UPnP 播放目标由 DLNA 插件负责 SOAP 控制和 stop。
- 前端切换播放设备时会先停止旧目标；后端 `PlaybackCore.set_target()` 也会调用旧输出插件的 `close()` 兜底。
- 没有 USB DAC 时不显示 MPD 设备，避免用户误以为浏览器访问 NAS 就能通过 MPD 在电脑上出声。
