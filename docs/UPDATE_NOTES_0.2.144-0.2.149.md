# fnAudio 更新说明：0.2.144 → 0.2.149

这份说明覆盖 0.2.144 之后到 0.2.149 之间的全部改动（`versionCode` 402 → 407），**按主题合并，不逐个版本列举**。
中间有些版本只为了修一条反馈而发，这里不再单独说明。

升级方向：**手机端建议升到本版**（登录相关的修复全在这里）；服务端如无特别需要可以不升，本区间没有破坏性改动。

---

## 一、手机端：FN ID 终于能从公网登录了

这是本区间改动最大的一块。

**以前会遇到的四种失败**，看起来像三个不同的问题，其实是同一条链路上的连锁故障：

| 你看到的现象 | 实际情况 |
|---|---|
| 填域名能登录，填 FN ID 就报「HTTPS 证书校验失败」 | 同一个账号、同一台设备，差别只在解析出来的地址写法 |
| 切「公网连接」或「速度优先」必定失败 | 走公网地址时根本没有可用的证书校验路径 |
| 登录成功后主界面立刻报证书失败 | 恢复连接时把「用 HTTPS」这个设置丢了，整段会话掉回明文端口 |
| 登录成功但曲库是空的，报「读取歌曲列表失败（响应体不完整）」 | 每个请求都先明文发一次、被服务器重定向到 HTTPS，重定向之后认证信息丢了 |
| 点登录直接闪退 | 令牌过期、回退到保存的密码重登时，在界面线程上关闭网络连接池 |

**真正的原因**（说人话版）：

1. **FN ID 解析出来的是 IP 地址，而 NAS 的证书是按域名签发的。** 用 IP 去校验证书，在任何客户端上都不可能通过——公共机构不给 IP 发证书。所以「填域名能登、填 FN ID 不能登」，问题不在账号也不在证书，而在地址写法。
2. **用 IP 登录本来就不该走"严格校验"这条路。** 现在的处理是：这类地址承认「无法验证」这个事实，但首次连上后把证书指纹记下来，之后一旦变化就拒绝（见第二节）。
3. **NAS 强制 HTTPS，所以任何明文请求都会被重定向一次。** 重定向会换端口、有时也换协议，原来的逻辑把它当成"换了一个服务器"，于是那次请求不再带认证信息，服务器返回的是登录页 HTML，界面自然就解析不出歌曲列表。

**现在的行为**：

- **速度优先**：先试局域网，再试公网；都不通时**自动改用中继**——以前只要勾了 HTTPS 就不会自动回落，必须手动切「中继」。
- **公网连接**：直连不通时直接告诉你是「端口未开放或被网络屏蔽，请改用中继或速度优先」，不再给出无关的证书或访问码错误。
- **同一局域网内优先走内网地址**，不再绕到公网 IP 再回来（很多家用路由器不支持这种回环）。
- **域名解析失败单独提示**：「无法解析服务器域名，请检查手机网络」，不再笼统地说「访问码验证失败」。

> **一个前提**：外网直连需要手机有 **IPv6**。这台 NAS 的公网 IPv4 端口没有做映射，所以纯 IPv4 环境下无法直连——那种情况会自动走中继，速度略慢但可用。想让公网 IPv4 也能直连，需要在路由器上把 `5667` 映射到 NAS 的内网地址。

## 二、证书：不再问你，改成自动信任 + 变更拦截

**「允许自签名证书」这个勾选框已经去掉。** 规则改成和飞牛官方 App 一致：

- 任何 HTTPS 设备的证书都直接接受，不再需要你预先授权；
- 第一次连上时记下这张证书的指纹；
- **以后这张证书一旦变了，立刻拒绝并提示**，不会悄悄换成别人的。

**为什么以前勾了还经常没用**：这个开关只对「手填域名 + 自签名证书」这一种情况生效。用 FN ID 登录、手填 IP、或者走中继时，程序根本不看它——所以你勾着也照样报证书错误。

**安全性没有丢**：防的不再是"第一次连的设备是不是自签证书"，而是"之后连的还是不是同一台设备"。证书被替换会当场失败。

## 三、播放设备列表：改成后台扫描

**以前**：每次点开「播放设备」都要现场扫一遍局域网，状态栏显示「正在扫描局域网」，得等几秒才出列表。

**现在**：设备列表由服务端在后台持续刷新，打开对话框直接看到上次的结果。后台在更新时显示「后台更新中 · N 台可用」，不再让你觉得"必须等它扫完"。手动点「重新扫描」仍然是立即重新发现。

---

## 四、音乐目录：只剩一个入口

**以前**：设置页有两个按钮——「+ 添加目录」调飞牛官方的目录选择窗口，「浏览服务器目录」是 fnAudio 自己的浏览。两个做的是同一件事。

问题在于**官方窗口看不到远程挂载**：它是白名单式的，只显示被申请的分组，而 SMB／NFS 共享挂在 `/vol1/@mountmgr/…`，不在默认分组里。想加一个局域网共享目录，只能绕到另一个按钮去加。

**现在合并成一个「+ 添加目录」**，直接打开 fnAudio 自己的目录浏览：

- 列出**卷根目录与所有挂载点**，本机盘和已挂载的共享都能进去，比官方窗口能看到的更多；
- 选好目录后点「添加当前目录」，再点「保存音乐库设置」——和以前一样，选中不会自动保存；
- 面板显示当前路径，可以「上一级」返回；卷根目录不会列出 `@appdata`、`@docker` 这类系统目录。

**顺带修的两处**：

- **目录健康按每个目录分别报告**：配了多个目录时显示「N 个目录」，哪个丢了或读不到会点名。以前只反映第一个目录，第二个挂掉时卡片还显示「目录正常」，而且一个目录坏了会连带把「立即扫描」锁死。
- **页面资源没加载全时会自己恢复一次**，并且在没读到已配置目录之前禁止保存——避免把原有目录覆盖成刚选的那一个。

对已经配置好的目录没有任何影响，列表里的路径原样保留。

## 五、应用中心图标

修掉了「应用中心列表里 fnAudio 显示灰底占位图」。

根因不在图片本身——服务端返回的一直是正确的那张。问题出在配置文件里图标写成了模板 `images/icon_{0}.png`，而**应用中心不做占位符替换**，把字符串原样拼进 URL，列表侧拿不到确切文件名就退回默认占位图（详情页走另一条路径，反倒正常）。现在改成具体文件名，与飞牛自带应用同一种写法。

图标本身也重画过一轮，以原版为基准逐像素测量重建，主体占到画布约 60% × 78%。

## 六、数播关机后 fnAudio 打不开

**改了什么**：启动时先让网页端口可用，再启动音频后端；同时把启动脚本等待端口的时间从 6 秒放宽到 30 秒。

**说明白一点**：这条是**加固，不是已确认的修复**。原本判断是"音频后端冷启动超时导致启动脚本把进程杀掉"，但实测没有复现——数播未接时启动只要 2.1 秒，把输出设备故意改成不存在的设备也只要 1.45 秒，日志里从来没出现过启动失败记录。真实原因仍在等现场证据。

改动本身是安全的（只让端口更早可用）。如果升级后仍然打不开，请提供那一刻的 `@appdata/info.log` 与 `cat /proc/asound/cards` 的输出。

## 七、手机端连 HTTPS 闪退

证书校验失败本身是**被正常捕获**的（所以你能看到那句报错），闪退发生在之后的处理路径上。这次给四处「会抛到界面线程却没人接住」的调用加了兜底：

| 位置 | 触发条件 |
|---|---|
| 内嵌浏览器的证书错误回调 | 连接档案尚未就位时回调先到，读空对象崩溃 |
| 自签名证书信任链装配 | 组装 TLS 栈失败时异常直接抛到界面线程 |
| 连接档案落盘 | 系统密钥库失效（改锁屏、系统升级）时写入抛异常 |
| 访问码请求 | 服务器地址为空、或请求器已关闭后重试 |

全部转成日志 + 错误面板提示，不再让进程退出。另外，认证的**启动**阶段原本在界面线程上做网络操作，强制 HTTPS 时会直接抛 `NetworkOnMainThreadException`，现在整个启动挪到工作线程，回调仍然回到界面线程。

## 八、电视端暂时下线

电视端客户端在这个区间里做过一版，随后**已暂停并从发布分支撤出**。原因是重构后的界面代码与手机端共用了包名和权限声明，导致手机安装包也带上了相机权限等无关能力。

现在发布的 APK 只面向手机／平板。电视端要恢复的话，会先把代码按设备类型彻底分开，再单独发一个包。**如果你之前装过电视端的 APK**（包名 `com.fnaudio.client.tv`，与手机端是两个独立应用），**它不会再随本版更新**；装本版手机包也不会覆盖或卸载它，需要的话自己手动卸载即可。

---

## 九、升级注意

- **手机端**：覆盖安装即可，**不需要重新登录**。之前勾过「允许自签名证书」的连接档案照常能用，那个值不再影响行为。
- 如果之前装的是我们自己构建的 debug 包，直接装正式包会报签名冲突（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），需要先卸载旧版。
- **服务端**：本区间没有破坏性改动，通过应用中心升级即可，连接档案与曲库索引会保留。
