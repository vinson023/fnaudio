# fnAudio 更新说明：0.2.144 → 0.2.147

本区间面向 **fnOS 服务端与手机客户端** 的变更集中在 0.2.146 与 0.2.147 两个版本。

| 版本 | versionCode | 主要内容 |
|---|---|---|
| 0.2.146 | 404 | 应用中心图标修复；音乐目录的浏览入口 |
| 0.2.147 | 405 | 三条现场反馈：数播关机启动、目录入口合并、安卓 HTTPS 闪退 |

> 0.2.145 只调整了独立安装包的入口，主应用（fnOS 服务端 / 手机客户端）没有变化，因此不在本说明内。

---

## 一、音乐目录：现在只有一个入口

**以前**：设置页的「音乐目录」有两个按钮——「+ 添加目录」和「浏览服务器目录」。前者调飞牛官方的目录选择窗口，后者是 fnAudio 自己的目录浏览。两个做的是同一件事，还容易让人以为是两种不同的操作。

**问题在于官方窗口看不到远程挂载**：它是白名单式的，只显示被申请的分组，而 SMB／NFS 共享挂在 `/vol1/@mountmgr/…`，不在默认分组里。所以想加一个局域网共享目录，只能绕到「浏览服务器目录」去加。

**现在合并成一个「+ 添加目录」**，直接打开 fnAudio 自己的目录浏览：

- 列的是**卷根目录与所有挂载点**，本机盘和已挂载的共享都能进去，比官方窗口能看到的更多。
- 选好目录后点「添加当前目录」，再点「保存音乐库设置」——和以前一样，选中不会自动保存。
- 面板显示当前路径，可以「上一级」返回；卷根目录不会列出 `@appdata`、`@docker` 这类系统目录。

对已经配置好的目录没有任何影响，列表里的路径原样保留。

## 二、应用中心图标

0.2.146 修掉了「应用中心列表里 fnAudio 显示灰底占位图」。

根因不在图标文件本身——服务端返回的一直是正确的那张 64×64。问题在 `src/app/ui/config` 里 `icon` 写成了模板 `images/icon_{0}.png`，而**应用中心不做占位符替换**，把字符串原样拼进 URL，列表侧拿不到确切文件名就退回默认占位图（详情页因为走的是另一个路径，反倒是正常的）。

现在改成具体文件名 `images/icon_256.png`，与飞牛自带应用同一种写法。图标几何也重画过一轮，以 0.2.x 原版为基准逐像素测量重建，主体占比调到 1.15（约画布 60% × 78%）。

---

## 三、数播关机后 fnAudio 打不开

**改了什么**：启动时先让 HTTP 端口可用，再启动音频后端；同时把启动脚本等待端口的时间从 6 秒放宽到 30 秒。

**说明白一点**：这条是**加固，不是已确认的修复**。原本判断是「音频后端冷启动超时导致启动脚本把进程杀掉」，但实测没有复现——数播未接时启动只要 2.1 秒，把输出设备故意改成一个不存在的设备也只要 1.45 秒，日志里从来没有出现过启动失败的记录。所以真实原因仍在等现场证据。

改动是安全的（只让端口更早可用）。如果升级后仍然打不开，请提供那一刻的 `@appdata/info.log` 与 `cat /proc/asound/cards` 的输出。

---

## 四、手机端连 HTTPS 闪退

**以前的观感**：连 HTTPS 时闪退，或者停在「HTTPS 证书校验失败」的错误页。

**说明**：证书校验失败本身是**被正常捕获**的（所以能看到那句报错），闪退发生在之后的处理路径上。这次给四处「会抛到界面线程却没人接住」的调用加了兜底：

| 位置 | 触发条件 |
|---|---|
| WebView 证书错误回调 | 连接档案尚未就位时回调先到，读空对象崩溃 |
| 自签名证书信任链装配 | 组装 TLS 栈失败时异常直接抛到界面线程 |
| 连接档案落盘 | 系统密钥库失效（改锁屏、系统升级）时写入抛异常 |
| 访问码请求 | 服务器地址为空、或请求器已关闭后重试 |

全部转成日志 + 错误面板提示，不再让进程退出。

这条同样**需要真机确认**。若仍闪退，`adb logcat -d | grep -A20 AndroidRuntime` 能直接指出是哪一条。

---

## 五、升级注意

- **手机端**：如果之前装的是我们自己构建的 debug 包，直接装正式包会报签名冲突（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），需要先卸载旧版。
- **服务端**：FPK 通过应用中心升级即可，连接档案与曲库索引会保留；已配置的音乐目录不受目录入口调整的影响。
