# fnAudio 更新说明：0.2.144 → 0.2.147

这一区间只有三个版本，内容集中在两件事上：**电视端**（0.2.145 / 0.2.146）与**三条现场反馈的修复**（0.2.147）。按「你会感觉到什么」分节，不逐版本罗列。

| 版本 | versionCode | 主要内容 |
|---|---|---|
| 0.2.145 | 403 | 同一个 APK 里加电视入口（遥控界面） |
| 0.2.146 | 404 | 独立的电视 APK（64 位 / 32 位）+ 电视端功能补全 + 应用中心图标修复 |
| 0.2.147 | 405 | 三条用户反馈：数播关机启动、网页端远程挂载目录、安卓 HTTPS 闪退 |

## 一、电视端：从「装了还是手机界面」到能遥控操作

**以前**：APK 装到电视上是手机界面。原因不是安装包不对，而是启动入口的声明不同——手机入口挂在 `LAUNCHER`，电视入口挂在 `LEANBACK_LAUNCHER`，只有标准 Android TV／Google TV 桌面按后者列图标，**国产电视和盒子的桌面基本只认 `LAUNCHER`**，于是点图标进的是手机登录页。

**0.2.145**：同一个包里加了第二个入口 `TvLoginActivity`（遥控可用的登录页），手机入口一行没动。两套界面共用同一份连接档案与认证逻辑——**手机登录过的 NAS，在电视上按一次 OK 就连上**。

**0.2.146**：拆出独立的电视包，两个 ABI 各一个：

| 包 | 包名 | ABI |
|---|---|---|
| `fnaudio-tv-<ver>-arm64-v8a.apk` | `com.fnaudio.client.tv` | arm64-v8a |
| `fnaudio-tv-<ver>-armeabi-v7a.apk` | `com.fnaudio.client.tv` | armeabi-v7a |

- 电视包里**只有一个图标**，点进去直达遥控界面，不会再误入手机页。
- 32 位库只放在电视包里，**手机包体积不受影响**。
- 电视端功能补全：侧栏加了「收藏 / 播放列表 / 搜索 / 设置」并改为可滚动（十项在 540dp 高度放不下），首页补了「类型 / 作曲者 / DSD / 随机 100」快捷入口，新增搜索页、播放列表页（列表→曲目两级，返回上一级）、设置页（连接信息、切换服务器、退出登录）。

一个提前说明：**电视端的界面重构（顶部 Tab + 双形态播放页）做过但没有发布**，代码单独留在分支上，不会出现在这三个版本里。所以电视端目前仍是侧栏版界面。

## 二、应用中心图标

0.2.146 修掉了「应用中心列表里 fnAudio 显示灰底占位图」。

根因不在图标文件本身——服务端返回的一直是正确的那张 64×64。问题在 `src/app/ui/config` 里 `icon` 写成了模板 `images/icon_{0}.png`，而**应用中心不做占位符替换**，把字符串原样拼进 URL，列表侧拿不到确切文件名就退回默认占位图（详情页因为这个路径不同，反而是正常的）。

现在改成具体文件名 `images/icon_256.png`，与飞牛自带应用同一种写法。图标本身的几何也重画过一轮，以 0.2.x 原版为基准逐像素测量重建，主体占比调到 1.15（约画布 60% × 78%）。

## 三、0.2.147：三条现场反馈

### 1. 数播关机后 fnAudio 打不开

**改了什么**：启动时先让 HTTP 端口可用，再启动音频后端；同时把飞牛启动脚本等待端口的时间从 6 秒放宽到 30 秒。

**说明白一点**：这条是**加固，不是已确认的修复**。我原本判断是「MPD 冷启动超时导致启动脚本把进程杀掉」，但在测试机上实测没有复现——数播未接时启动只要 2.1 秒，把输出设备故意改成一个不存在的设备也只要 1.45 秒，日志里从来没有出现过启动失败的记录。所以真实原因还在等现场证据（应用中心是转圈、弹错误，还是点图标无反应）。

改动是安全的（只让端口更早可用），但如果升级后仍然打不开，请提供那一刻的 `@appdata/info.log` 与 `/proc/asound/cards` 输出。

### 2. 网页端挂不上 SMB 远程挂载目录

**以前**：手机上能把局域网 SMB 目录加进音乐库，在飞牛管理界面里打开 fnAudio 却选不到。

**原因**：两边的入口不同。网页端只能走飞牛官方的目录选择器，而这个选择器是**白名单式**的——只显示你申请的分组。我们只要了「我的文件 / 其他共享 / 收藏」，**漏了「远程挂载」**（SMB/NFS 挂在 `/vol1/@mountmgr/…`）。手机端走的是另一条路（服务端目录浏览），所以一直能加。

**现在**：
- 选择器补上了「远程挂载」与「外部设备」两组，侧栏里能直接看到挂载的共享。
- 设置页「音乐目录」旁新增常驻的**「浏览服务器目录」**按钮——手工写进 `/etc/fstab` 的挂载点可能不属于任何分组，这条路径保证兜得住。
- 后端的路径校验没有放松：`/vol*` 本来就在允许范围内。

### 3. 安卓客户端连 HTTPS 闪退

**以前的观感**：连 HTTPS 时闪退，或者停在「HTTPS 证书校验失败」的错误页。

**说明**：证书校验失败本身是**被正常捕获**的（所以你能看到那句报错），闪退发生在之后的处理路径上。这次给四处「会抛到界面线程却没人接住」的调用加了兜底：

| 位置 | 触发条件 |
|---|---|
| WebView 证书错误回调 | 连接档案尚未就位时回调先到，读空对象崩溃 |
| 自签名证书信任链装配 | 组装 TLS 栈失败时异常直接抛到界面线程 |
| 连接档案落盘 | 系统密钥库失效（改锁屏、系统升级）时写入抛异常 |
| 访问码请求 | 服务器地址为空、或请求器已关闭后重试 |

全部转成日志 + 错误面板提示，不再让进程退出。

这条同样**需要真机确认**：我手上没有能跑这个包的安卓真机（APK 只带 arm 库，模拟器是 x86 装不上）。若仍闪退，`adb logcat -d | grep -A20 AndroidRuntime` 能直接指出是哪一条。

## 四、升级注意事项

- **手机端**：如果之前装的是我们自己构建的 debug 包，直接装正式包会报签名冲突（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），需要先卸载旧版。
- **电视端**：先确认识别哪个 ABI——64 位盒子装 `arm64-v8a`，老盒子装 `armeabi-v7a`。两个包包名相同，不能同时装。
- **服务端**：FPK 通过应用中心升级即可，连接档案与曲库索引会保留。
